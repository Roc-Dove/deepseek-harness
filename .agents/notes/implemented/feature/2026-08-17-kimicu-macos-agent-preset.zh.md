# Agent Note：随附的电脑操作预设连接另行安装的 KimiCU

Status: implemented

[English](2026-08-17-kimicu-macos-agent-preset.md) | 中文

## 问题

可用的电脑操作组装原本只存在于一名开发者的 `DSH_HOME` 下。这能解释本机选择器，却不能让干净安装得到同一个界面：打包后的桌面端会创建新的应用专属 home，移除源码补丁变量，而且绝不会复制构建者的预设。如果把这个 home 复制进安装包，还会越过桌面发行边界，把机器本机状态当成产品配置，而不是提交经过审查的配置。

KimiCU 不是 Harness 依赖。它是另一个 macOS 应用，有自己的发行版、可执行文件，以及屏幕录制和辅助功能授权。因此，看见预设不能代表 KimiCU 已安装或已获授权。它的工具能够点击、输入、按键、滚动和读取屏幕；如果没有 Harness 的明确审批边界就暴露这些工具，就会把一次 macOS 权限授予变成模型的无人值守权限。

## 决策

CLI 把 `config/agent-presets/computer-use` 作为 system preset 随包提供。它遵循[常驻 preset 组装](../architecture/2026-08-08-per-preset-standing-mounts.md)：完整的标准模式组装仍可在单个文件中阅读，额外的一行 `@deepseek-ai/dsh-mcp-client` 连接 `/Applications/KimiCU.app/Contents/MacOS/kimi-cu mcp -s user`。元数据顺序把**电脑操作**放在既有四种模式之后，Web locale 表则提供权威的中英文名称和描述。

安装包只携带这份经过审查的配置与通用 MCP 客户端，不携带 `KimiCU.app`、下载地址、macOS 隐私授权或任何开发者用户数据。为本集成验证的是 KimiCU 0.5.8，它只有 arm64 架构，并要求 macOS 14 或更高版本。因此，菜单文案与桌面指南会把 Apple 芯片和 macOS 14 写成已经验证的边界，说明屏幕录制与辅助功能权限都直接授予 KimiCU，并要求安装应用或更改权限后重启 Harness。在没有核实发布方来源时，仓库不会虚构下载镜像，也不会要求用户绕过 Gatekeeper。

KimiCU 缺失时属于非致命的可选依赖。MCP 行设置 `failOnStartupError: false`，所以可执行文件无法连接时，预设仍会提供标准模式工具；它还设置 `reconnect.enabled: false`，避免一次选择触发反复失败的启动循环。这种状态下不会注册任何 `mcp__kimi-cu__*` 工具；KimiCU 可用后，通过重启 Host 恢复。

MCP 客户端新增可选的 `requireApproval` 设置，本预设会启用它。每个由此产生的 MCP `ToolDefinition` 都拥有 `requiresApproval`；`ToolRuntime` 在可重排的 `tools/pre-execute` waterfall 之后应用这项要求，因此监听器返回允许也不能削弱它。注册时会捕获内部不可变的执行、输出、schema 与审批契约，同时让 `get()` 保留既有消费者依赖的公开 definition 身份。每次调用还会快照并在运行时封住名称与参数。因此，替换 definition、修改回调、修改参数，或在等待审批期间交换 definition，都会关闭式失败，或者继续使用被批准的精确契约，而不能改变审批所授权的内容。没有组装审批应答器时，调用会在 `callTool` 前失败；拒绝也同样不会发起外部请求。

Persona 只会在 KimiCU 限定工具确实存在时使用它们，并明确禁止经标准模式 Shell 直接启动或驱动 KimiCU。纯文本路由依赖辅助功能文本；只有当前模型路由声明图片输入时，返回的截图才可作为视觉证据。这是能力指引，不是操作系统沙箱：另行获批的 Shell 命令仍可启动外部软件，macOS 权限也授予 KimiCU 进程，而不是某一次 Harness 工具调用。

当前的 preset discovery 不区分平台。因此，这个经过审查的目录会进入 CLI tarball 与每个平台的桌面后端。Windows 与 macOS Intel 也可能列出该行，但经过验证且只有 arm64 架构的 KimiCU 无法在那里连接。产品文案会如实写明这个限制，而不会假称只有受支持的 Mac 能看见该行。桌面产物验证要求五个 preset 文件对完整存在，dsh npm 载荷门禁也要求电脑操作的两个文件均在包内。

## 曾考虑的替代方案

**把开发者的 `DSH_HOME/.agent-presets/computer-use` 复制进安装包。** 拒绝，因为这会把本机可变目录当作发行来源，并削弱凭据、会话、端点、补丁与构建者路径不得进入桌面产物的约束。

**把 KimiCU 与 DeepSeek Harness 一起打包。** 拒绝，因为 KimiCU 有自己的发行、许可、签名、更新生命周期和 macOS 隐私引导。本仓库没有经过审查的再分发权或打包机制，而且用户已经明确接受另行安装它。

**KimiCU 缺失时让整个预设失败。** 拒绝，因为选择器需要在外部前置软件安装前就展示该能力。保留标准模式能提供一个诚实的降级状态；描述和指南会解释电脑操作工具为何缺席。

**保留自动重连。** 对缺失的应用予以拒绝。十次指数退避 spawn 只会增加日志噪声与后台工作，无法帮助必须安装应用或修改系统权限的用户。重启更加明确且确定。

**把 macOS 权限当作 Harness 审批。** 拒绝，因为辅助功能与屏幕录制会广泛授权 KimiCU 进程，却不能表达用户是否同意某一次由模型生成的点击、按键或屏幕读取。

## 结果

干净安装现在可以显示电脑操作预设，而无需导入任何开发者文件。在准备好的 Mac 上选择它，会组装标准模式能力与 KimiCU MCP 工具；在没有 KimiCU 的 Mac 或其他平台上，它仍是没有 KimiCU 工具的标准模式。这个区别会显示在本地化文案中，也会作为外部前置条件写进文档，而不是藏在失败的会话后面。

电脑操作调用会增加一次审批往返。这是在模型输出经已注册 MCP 边界变成操作系统输入时刻意加入的阻力。把审批策略设为 never 的部署会拒绝这些调用；具有交互式应答器的部署可以逐次允许。一个真实组装且不需要密钥的 transcript 会同时证明边界两侧：审批等待或被拒绝时，外部 fixture 收不到调用；`allowed-once` 后只收到一次调用。

KimiCU 可以返回辅助功能树文本、可见应用内容与截图。这些结果可能进入选中的模型服务商与持久会话历史。默认 DeepSeek 路由只支持文本，不能检查截图像素；视觉理解需要声明图片输入的路由，默认禁用的 Vision Bridge 也不会自动描述 KimiCU 截图。常驻 preset generation 及其管理的 MCP 子进程会一直存活到 Harness 进程退出，而不是在用户切换会话或预设时结束。这些数据流与生命周期事实会作为明确的用户约束保留。

该组装遵循既有随附 preset 约定，复制了标准模式。今后修改标准模式名单时也必须考虑电脑操作，shell 平台测试会覆盖两份副本。未来可以增加平台可用性 schema，让非 macOS 名单不再返回该行，并在选择器显示安装/权限健康状态；那属于另一个产品改动，不能用本次不准确的声明代替。
